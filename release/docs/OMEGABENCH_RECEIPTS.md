# OmegaBench local evaluator receipts

The `attach-benchmark-receipt` Evolve action retains an authenticated report for a
sealed benchmark. A named owner supplies `export` and `receipt`, using the current
graph revision. Trusted host startup code must provision
`hive.benchmark_receipt_verifier = ReceiptVerifier(ledger_path, trusted_keys)`.
Default: absent, requests refused. No public route, request field or environment
setting configures trust in this candidate. Platform owns startup/lifecycle;
close the verifier on shutdown. Keep the persistent ledger outside subject mounts,
with host-only directory permissions. Do not discard it on restart.

`trusted_keys` maps `(issuer, key_id)` to at least 32 random bytes provisioned out
of band to the host and evaluator. Never put keys in source, logs, receipts,
graphs or subject environments. No live key is included or generated by this
candidate. `issue()` binds the full registration seal, both subject pins,
evaluator/dataset/environment pins, complete normalized export digest, swarm,
benchmark record, evaluator/run identity and custody-manifest digest.

This uses HMAC-SHA256 in the standard library. The verifier holds the same secret
as the issuer, so it can also issue MACs. It establishes authentication within
that local trust arrangement, not public-key signatures, non-repudiation or
independence from the host. A malicious trusted issuer can authenticate false
reports. Custody, grading correctness and subject execution need separate checks.

The ledger rejects different receipts reusing an issuer/run identity, including
across swarms and key rotations. Identical retries remain safe after a registry
append failure. SQLite transactions serialize competing admissions; key
revocation persists and applies to retries. Historical Evolve records are
immutable: revoking a key refuses future admission, but does not silently rewrite
old records. Their current trust must be rechecked by a reviewer before use.

Authentication metadata carries no answers, raw responses, keys or MAC envelope.
The existing statistical assessment stays `unverified-import`, custody remains
unverified, review pending, candidate_evaluated=false and adoption=false. The
owner-retention action does not run the candidate. Public fixture results cannot
become independent evidence through a receipt.

Qualification uses invented disposable keys, synthetic sessions, temporary SQLite
stores and no subject/provider process. It does not prove real identity-provider
authentication, OS isolation, hidden answers, meters or independent evaluation.
Before deployment, platform must configure/persist trust and agree the worker
execution boundary with Bench. The hidden worker, real cohort and paid seed
experiment remain outstanding.
