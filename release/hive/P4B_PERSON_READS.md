# Person decision and Studio reads

`GET /api/me/decisions` collects five independently authorized categories. `GET /api/me/studio-sessions` uses the same own-Studio projector. These reads return existing state; they do not grant, answer, provision, dispatch, renew or repair anything. Mutation routes must still authenticate and authorize their action when it happens.

Both routes first require a current human password or SSO session. A dedicated positive preflight precedes the inherited operator transport checks so bootstrap, service, unknown-kind and mismatched credentials return 401 even when a query is malformed. The normal operator checks still run. The genuine migrated local password form may lack a stored principal/expiry; it remains the local operator. SSO requires an explicit current allowed family identity or enabled named person with a current admin/member role and expiry. Viewer fallback is never proof of personhood. Existing general authentication helpers are unchanged.

Ask intents and Studio rows additionally require the existing named SSO-person semantics. A valid aggregate session grants no other person's records. In particular, admin audit access does not become ownership of their Ask turns, requests or Studio sessions. Role, session, person and item authority are rechecked before final emission. The response is a point-in-time read, not a lease.

The decisions response is `{schema:"hive.me-decisions/1",categories:{approvals,limit_requests,own_requests,ask_intents,studio_sessions}}`; each category is exactly `{items,next_cursor}`. The Studio response is `{schema:"hive.me-studio-sessions/1",items,next_cursor}`. Items have only the following fields:

- Approval: `kind,id,agent_id,skill,risk,state,created_at,answers`. State is pending; risk is medium/high. Answers has exactly once/for/always/no/never booleans. Lasting positive allow and durable Never are different choices. Current template ask/deny ceilings cap positive answers; exact program and high-risk actions cannot advertise lasting positive allow. The actual policy HIGH_RISK skill set also caps positive answers when an inconsistent stored row says medium; durable Never remains separate. Exact program Never is false because the inherited handler does not record a standing deny for it. A person-only exact action cannot advertise Once to the local password operator.
- Limit decision: `kind,id,agent_id,state,created_at,answers`, with approve/adjust/decline booleans. Only the currently addressed owner sees a pending decision, after current key existence/ownership, requester/addressee, selected mind/key, current user/payer and visibility checks. `*` is an explicitly addressed broad-owner request with no selected mind; it never selects a provider default. A password operator wildcard requires a positively stored hive owner; missing required ownership is 503, with no migration. An enabled named wildcard addressee can establish their own authority independently. A first grant may intentionally switch billing from the named key owner to the requester, so current billing may be either of those two while the current user must still be the requester. Another current user or payer cannot inherit the old request.
- Own request: `kind,id,request_kind,state,created_at`. Kinds are mind/allowance/swarm_access; states pending/granted/declined. This category is only person_requests, not a new requested-limit discriminator. Exact requested_by is required even for admins. Existing hide_others_personal suppression remains; members can see their own pending access request before gaining target access because no target, payload or capability is projected.
- Ask intent: `kind,id,intent_kind,state,created_at,updated_at`. Own undeleted intent and turn, current kind role and existing integrity audit are required. Kinds are code.request/studio.session; open states pending/refused/dispatching. Expired pending/refused and linked/abandoned rows are excluded. Dispatching is information only, not a recovery or replay action. Audit mismatch remains 409.
- Studio: `kind,id,state,created_at,updated_at`. Exact owner and current named-person/swarm visibility are required, including for admins. States are active/paused/stopping/stopped/held. Ledger, piece, app pin, model, key, tools, costs and Stop capability are absent. Both endpoints use identical item projection.

IDs/skills are bounded to 128 characters and timestamps to 64; unknown or malformed projectable values are refused rather than stringified or truncated. Private request text, approval commands, arguments, grant/key payloads and Studio content are not included.

Queries are closed. Both routes accept limit, a strict decimal integer 1–50 (default 25); the existing operator token transport remains available. Decisions accepts separate approvals_cursor, limit_requests_cursor, own_requests_cursor, ask_intents_cursor and studio_sessions_cursor. The standalone Studio route accepts cursor. Duplicate/unknown query fields are 400 after authentication. Independent versioned cursors carry only category, last emitted authorized id and created_at, with a 512-byte UTF8 bound. They grant no authority; wrong category/malformed cursors are 400 and a missing/revoked anchor is 409 cursor_stale.

Categories sort by created_at descending then id descending. Principal restrictions precede selection where the schema supports them; authorization precedes counting and cursor emission. Each category scans at most 500 candidates. If that ceiling prevents an honest completion/continuation decision, the request returns 503 read_scan_bound instead of a false empty/complete page or a hidden last-scanned id. Responses are checked as serialized UTF8 JSON, including envelopes/cursors: at most 1 MiB for decisions and 256 KiB for Studio. Those are protocol-byte limits, not Python heap or RSS caps. Existing closed field limits generally make these response maxima conservative.

Default personal visibility is evaluated only for the current item's named targets. Extraction is limited to 512 nodes, 64 distinct identifiers, depth 3 and 200-element lists, with at most 16384 targeted visibility lookups per request. It never collects global personal-mind/swarm inventories or relies on the inherited two-second hidden-id cache. Ordinary admins retain access to nonpersonal private rows, while another person's unshared personal rows remain suppressed. Member own requests remain informational; a target access request is not hidden merely because access is not yet granted. Limit-request requester visibility uses the same bounded target evaluator. Unknown/oversized target metadata fails 503 rather than truncating the authority check.

Current program/template authority is checked without calling Programs._ready/check_integrity, PersonSwarms.current, provisioning or app hooks. Those inherited paths can publish, mutate or transitively migrate an owner. The new reader mirrors recorded template consent/digest, oldest own-provider-key selection, monthly total, finished slot, mind owner/options, current action/attachment and grant predicates. A stored hive owner is read directly; a missing required owner is unknown, never an invitation to migrate it. Current billing reuses the source-reviewed pure Hive.user_for/Studio principal chain and reads guest/grant predicates without OwnHive.access/owner.

Pinned program integrity uses a finite read-only inspector on the registered entry's own root, never a request path. It preserves supported plain-file source-digest ordering/skips and pin/environment checks. Limits are 64 directories, 512 source files and 8 MiB read per program; all encountered entries, including ignored names, are bounded before collection/sorting (4096/program, 16384/request), with 32 MiB aggregate content and 65536 cached identity checks per request. Symlinks, unsupported files, ancestry/identity changes, unknown metadata and overflow return a bounded failure. Source reads use nofollow/nonblocking regular-file descriptors and before/after identities; final emission rehashes each pinned program once. No environment/grant/source content is exported or logged. These cooperative checks are not an OS snapshot, hostile Python sandbox or a whole-host RAM/time guarantee.

An absent program pin is distinct from a declared null/invalid pin or an invalid pins registry. Only absence means an unpinned legacy app; declared invalid authority fails 503 and cannot skip the inspector, including at final emission.

Expected current denial/revocation omits an ineligible item. Integrity/audit corruption, unresolved authority and bounds produce an explicit 409/503, not an empty permissive category. No DB transaction or mind mutex is held across current-authority callbacks or filesystem inspection. Existing inherited writers remain unchanged: notably OwnHive.decide's stored-address authority behavior is not silently repaired by this GET's stronger current eligibility checks.

## Tests

The real-HTTP regressions in `hive/tests/test_me_decisions_p4b.py` exercise personhood before empty/query paths; category ownership, roles and bounded per-item visibility; P2 consent/template/key/month/current-program and attachment changes; current limit authority and first grants; integrity 409; both routes' tie pages, stale cursors and closed queries; the 500-scan refusal; UTF8/closed projection; no-write/effect traps; high-risk inconsistent rows; declared invalid pins; missing required owner; and bounded pinned-source/environment/FIFO/symlink behavior. The standalone Studio route has direct own-scope, wrong-category, revoked-anchor, query, envelope and wire-byte checks. All data is synthetic.
