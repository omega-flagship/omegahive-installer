# OmegaEvolve begins as an Omega and an Iter

the owner's direct correction establishes two initial evolving subjects: one real
`kind=omega` mind and one real `kind=iter` mind. Both evolve themselves and can
propose improvements to the other. Neither exists only as the other's baseline.
The project also learns how to improve its improvement process.

Each subject retains its identity, source revisions, memory and recovery history.
They share hive knowledge under item visibility and access grants. The shared
objective remains RSI toward Beneficial General Intelligence and beneficial
superintelligence, with objective self-amendment disabled for now. The hive owner
adopts OmegaEvolve changes. Other minds offer contributions, not unrestricted
write authority over either subject.

`hive.core.evolve_seed.seed_plan()` provides exact operator creation fields and
budget requirements. `inspect_pair()` checks the returned metadata: exactly one
Omega and one Iter in the research swarm, distinct IDs, separately pinned source,
stopped seeds, supported Docker Iter driver, one combined $10/day swarm rule and
$0.50 total per seed for the first $1 bootstrap. It drops credentials and does not
claim runtime isolation, custody or adoption proof. Host provisioning, grants and
sandbox verification remain explicit platform operator steps.

## First bounded cycle

1. Provision the pair stopped, give each its own memory and isolated candidate
   area, pin the initial runtime/source, and verify Iter sandbox and gateway spend
   accounting. Omega's current shared-core symlink must not become a write target.
2. Apply the combined daily cap and both total bootstrap caps. Post an update hold
   and use the existing bounded-run coordinator; stop both on timeout/failure/cap.
3. Each mind inspects itself and supplies a source-pinned improvement hypothesis
   for itself and its peer, with expected benefit, uncertainty, evaluation plan
   and rollback/memory-continuity requirements. This is a research proposal cycle.
4. Test each candidate against that subject's own pinned baseline. Evaluate
   Omega alone, Iter alone and their cooperation where the hypothesis depends on
   cognitive synergy. Count cost, failed attempts and adverse outcomes.
5. Submit evidence to independent review and hive-owner adoption. Preserve source
   corrections and new memory deltas. Start a subsequent cycle from an actually
   adopted revision only after an adoption receipt and restart/recovery check.

The initial protocol tests prove bookkeeping constraints. They do not prove
measured improvement, recursive self-improvement or beneficialness. R17's result
checker continues to refuse completion until evaluation and review are wired.
The Hyperon theory review informs the research route: reflection/self-modeling,
reasoning/program learning and cognitive synergy require measured experiments;
formal reflection or a fixed point alone does not establish convergence or benefit.
